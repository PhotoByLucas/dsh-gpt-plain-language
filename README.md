# GPT 说人话

[English](README.en.md) · [实现说明](docs/architecture.md) · [贡献指南](CONTRIBUTING.md)

**让 GPT 先说重点、少用术语、给能照做的下一步。** 这是一个 DeepSeek Harness（DSH）插件：选 GPT 正常聊天，不用每次手动加提示词。DeepSeek 等非 GPT 模型不会收到这段默认提示。

## 为什么做这个插件？

在我看来，GPT 本质上更像一个**做题区** 模型 ：题目和目标都明确时，它很擅长按题作答；但在日常聊天、解释问题和一起推进工作时，我觉得它远不如 Claude 好用。我更喜欢 Claude 默认的表达方式：直接、自然，不用先交代一长串提示词才说到重点。这是我的使用感受，不是跑分结论。

GPT 的回答有时绕、重点靠后，或者讲完概念却没告诉你下一步做什么。手动复用 `/i-have-adhd` 和 `/eli5` 有帮助，但每次输入很麻烦。而原版 `/eli5` 是 HTML 图解技能，不适合每条普通消息都触发。本插件只把两者的**聊天表达规则**做成 GPT 的默认提示。

## 安装与试用

1. 确认 DSH 版本为 **`0.2.2-rc.5`**。当前插件声明了这个确切版本；其他版本尚未验证。
2. 将仓库克隆到本地：`git clone https://github.com/PhotoByLucas/dsh-gpt-plain-language.git`。
3. 在 DSH 的 **插件 → 添加插件** 里选择克隆下来的仓库目录，启用 **GPT 说人话**。本地目录安装会链接源文件，安装后不要移动或删除目录。
4. 新建会话，选一个 GPT 模型，发一句「用一个生活例子解释什么是缓存。」无需输入斜杠命令。

## 默认规则

| 来源 | 加给 GPT 的规则 |
| --- | --- |
| `i-have-adhd` | 开头直接给答案或一个小动作；多步任务编号，每步可执行；汇报已完成的成果，错误说清原因和修法，必要时给明确时间估计；有未完成事项时只留一个下一步；不加客套、跑题或重复总结。 |
| `eli5` | 用日常词、短句和有帮助的具体例子；先讲清意思再介绍术语；跟随用户语言，不居高临下，不省略重要限制。 |

你明确要求的格式和详细程度优先。普通聊天不会因为这段提示生成 HTML，也不会为了启用风格追问主题；如果你的环境里有原版 `/eli5`，仍可按原来的方式手动调用。

## 关闭与边界

- 想在当前会话停止 ADHD 风格，可以说 `normal mode` 或 `stop adhd mode`。这是给模型的指令，不是插件的硬开关，也不关闭 ELI5 表达规则。
- 想停用整个插件，在 **插件 → GPT 说人话** 关闭，再用新会话确认，避免既有会话历史里的旧提示干扰。
- 按 DSH 的模型 ID 匹配，不按供应商。`gpt-6.2-sol`、`openai/GPT-4o` 会命中；`o3` 或不含 GPT 前缀的自定义别名不会命中。
- 表达规则是内置改写，不读取你的本地技能文件，不调用斜杠命令，不额外发请求。它只是提示，不能保证每条回答都遵循。

## 验证与开发

在 DSH `0.2.2-rc.5` 的实际新会话中，已通过本地请求日志确认 `codex` 路由的 `gpt-6.2-sol` 请求包含两组规则。GPT → 非 GPT 切换行为由单元测试覆盖，未作为跨供应商的端到端测试结论。

使用 Node.js 24，不需要安装依赖：

```sh
node --check index.js
node --test
```
